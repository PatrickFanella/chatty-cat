# Optional device sync demo

Build with `npm --prefix web run build`, then run `go run ./web/test-support/device-sync` from the repository root. Open http://127.0.0.1:5196/?channel=one&video=off in two independent browser profiles. This fixture uses the real session and sync handlers with synthetic Alice (42) and Bob (43) accounts, no real Twitch credentials or chat/moderation writes. Its temporary 0700 storage path is printed on startup and retained on shutdown.

1. Sign in as fixture Alice on device A, open Device sync and use Fixture: seed device A. Reopen the panel, fetch revision 0, select all three categories and review publishing. The exact JSON includes Device A, size 18 and bookmark-A; private-note-A, nickname canaries and reader anchors are absent.
2. Use Fixture: drop next publish receipt and confirm. The fixture commits the write but returns HTTP 503. Confirm the same reviewed request again. The receipt succeeds; Fixture: show public/private counts reports two PUT attempts and one revision change.
3. In the second browser profile, sign in as Alice, seed device B, reopen the panel and fetch. Select all categories and review apply. The summary reports removed records, the active workspace and one removed bookmark with private annotations retained locally. Confirm. After reload the counts show Device A, size 18 and bookmark-A without private annotations, privateBackupHasB=true and aliasRetained=true.
4. On another Alice device, fetch and stage a publish review. Delete the active server snapshot from the first device. Confirm the stale publish: it is rejected with a revision conflict. Fetch again to observe an empty document with a new tombstone revision, rather than resurrection of the old document.
5. Close the panel and enable privacy. The review JSON is empty and the panel closes; opening it never reconnects automatically. Account changes also require a new connect/review. Use Bob to inspect his separate empty snapshot. The automated real-session API suite verifies cross-account header rejection, CSRF and logout during body read.

Verified in the native T3 preview on 2026-10-13: steps 1–4, close/privacy review clearing, exact JSON private-field omission and retained local annotations. The native test used separate saved-login profiles and the actual built UI. Cross-account authorization is covered by the real-session API tests; this run did not claim a native Bob sign-in or production account acceptance.

Regression coverage includes public-only projection, server/browser portable-schema compatibility, active-workspace selection, retained local reader positions, private-backup conflict protection, quota rollback, interrupted-apply leases, stale local edits, account/session changes, response bounds, server revision changes and explicit local-backup clear review. Full frontend, build, type checks, Go race tests, vet and lint are recorded in the PR. The pinned 515-row parity inventory is checked separately; a successful fixture does not establish live provider acceptance.
