# Reviewed provider activity demo

Build the web app and run `python3 web/test-support/provider-events-browser-fixture.py` from the repository root. Open `http://127.0.0.1:5198/?channel=room&video=off` in a fresh browser profile. All provider calls in this fixture are synthetic; it announces no real account.

1. In **Provider and badge preferences**, allow BTTV and 7TV activity sharing, review and apply. This may open the BTTV read socket, but sends no account announcement or presence write.
2. Open **Provider activity**. **Start** is disabled until **Review provider activity** checks the current login, operator configuration and linked 7TV identity. Review lists the account and one fixed selected channel, the five-minute interval and stop conditions. It expires in 60 seconds.
3. **Start reviewed provider activity** sends one BTTV `broadcast_me` frame using the signed-in Twitch ID and selected channel ID, and one 7TV presence POST using the matching linked 7TV ID. The synthetic fixture records it in `window.fixtureActivityWrites`; it contains only `kind:1`, the channel ID and platform `TWITCH`. Credentials are omitted and no Twitch token is included. A BTTV socket send does not prove provider delivery.
4. **Return to chat; keep activity running** closes the dialog and leaves a visible **Provider activity active** button. Ordinary dialog close stops the session. **Stop provider activity** also stops it.
5. Enable privacy mode. The activity button becomes inactive, the modal closes and the BTTV socket closes. Neither the activity session nor provider sockets resume automatically when privacy ends. The fixture retains exactly one announcement and one presence attempt.

The native T3 built-app preview passed this flow on 2026-10-13 with one unchanged public chat socket. It recorded exactly one announcement and one presence POST after Start, none during preference application or review, and no active session after privacy. Automated checks cover five-minute recurrence, current-profile/selected-channel guards, expiry, missing or mismatched linked accounts, late responses, authentication changes, capability checks, cancellation and uncertain-write cooldowns. Full frontend suite: 729 tests. Type check/build, focused Go sync race tests, vet and lint passed.

The implementation follows the pinned [BTTV announcement shape](https://github.com/Chatterino/chatterino2/blob/v2.5.6/src/providers/bttv/liveupdates/BttvLiveUpdateSubscription.cpp) and [7TV presence shape](https://github.com/Chatterino/chatterino2/blob/v2.5.6/src/providers/seventv/SeventvAPI.cpp). Read-only probes verified patrick__eff has public linked profiles on both providers and that the 7TV presence endpoint accepts the production origin's CORS preflight. No live activity POST or account announcement was sent by those probes. Production acceptance remains open until the deployed app runs this reviewed flow with the real signed-in account.

This browser adaptation announces one reviewed selected channel per session. It does not automatically announce across every workspace channel or restore activity after a reload. Stopping prevents future sends; it cannot retract a presence already observed by the provider.
