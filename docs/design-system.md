# Chatty Cat design system

Status: direction B, Pixel cat, selected by the owner on October 11, 2026 from four
candidates, with the palette system added and the identity approved the same day. This document is the editing source for
the product's interface rules and identity. The SUBCULT Studio pack in
`subcult-tv/studio/brands/chatty-cat/` holds the mark masters, the palette table, the
promotional artwork and the web-asset generator, and copies this file with hashes. Edit
interface rules here; edit artwork and palettes there.

The retained chat presentation is not a redesign surface. `docs/architecture.md` sets the
original app's dense, configurable chat as the parity reference, and its palette axes,
presets, fonts and resource content are AGPL material attributed in `NOTICE.md`. The
identity applies to the shell, the icons and public material. It does not change how a
message row looks.

## Identity

**Name.** Chatty Cat, two capitals, in prose and in the manifest. The wordmark is
`chatty_cat` in Cascadia Mono Bold; use that spelling only in the wordmark. The
repository, Go module and image names are `chatty-cat`.

**What it is.** A self-hosted Twitch chat client that merges up to six channels into one
scrollback and keeps the user's display settings. It rebuilds mxmilkiib's HasanAbi Chat
Thing and Twitch Chat Relay in Go and TypeScript. It is in migration; the original app
stays up until the parity gates in `docs/parity.md` close.

**Mark.** An eight-bit cat face, twelve cells wide and ten tall: two ear cells, two eye
gaps and a two-cell cursor for a mouth. Every cell is solid, so it reads at 16px as a cat
and at 32px as pixel art. The shape is the `pixels` grid in the Studio `brand.json`.
Keep a quarter of the mark's height clear on all sides. Render it with crisp edges; never
smooth, rotate or outline it. The lockup is the cat beside `chatty_cat`, 160px wide or more.

**Retired.** The PWA icon was Twitch's glitch glyph in amber. It is not part of this
identity and must not return in any colour.

**Web assets.** `web/public/favicon.svg`, `favicon.ico`, `icon-src.svg`,
`mark-themed.svg`, `icon-192.png`, `icon-512.png`, `icon-maskable-512.png`,
`apple-touch-icon.png`, `og.png` and `palettes.json` are generated by the Studio pack in
the phosphor palette; `web/public/brand-export.json` records their source and hashes.
Regenerate in Studio and copy. Do not edit the copies.

**Voice.** Quick, practical, a little dry; chat vocabulary used correctly (rooms, the log,
scrollback, backfill). Says it is a self-hosted client in migration, names the lineage and
never implies a Twitch product. Full voice in the Studio voice guide; facts from the
claims register entries C-CHAT-01 to 04.

## Palettes

A brand palette is four colours. `bg` is the canvas, `fg` the text, `face` the cat and
the wordmark, `cursor` the mouth, the live block and the sparkline. Panel, line and muted
tones are mixes of `bg` toward `fg`. Rules: `fg` on `bg` at 4.5:1 or better; `face` and
`cursor` at 3:1 or better; each colour has one job and `face` is never body text.

| Palette | bg | fg | face | cursor |
| --- | --- | --- | --- | --- |
| phosphor (default) | `#0b0f0c` | `#cfeedd` | `#7dff9a` | `#e8a33d` |
| amber | `#000000` | `#ffa326` | `#ffb249` | `#5edb81` |
| gray (the app default) | `#1d2229` | `#e8eff9` | `#e8a33d` | `#5fd98a` |

Thirteen more follow the remaining app colours at their default shades (violet, green,
ember, red, wine, solarized, nord dark; lavender, sepia, salmon, ice, cream, mirc light).
The full table with measured contrast is `tokens.json` in the Studio pack and
`web/public/palettes.json` here. The two phosphor palettes are the brand's own; the other
fourteen exist so the cat always has a match for whatever colour the user picked.

**Customising.** Three levels, cheapest first:

1. The header cat is inline SVG with classes `cat-face` and `cat-cursor`. `style.css`
   fills them from `--cat-face` and `--cat-cursor`, falling back to `--accent` and
   `--good`, so the cat already follows every colour, shade and finish the user chooses.
   Set the two custom properties to retheme it without touching the palette axes.
2. Build-time: `build.py --palette <name>` in Studio exports icons and layouts in another
   palette; `--custom "bg=,fg=,face=,cursor="` builds a one-off.
3. Add a row to `palettes` in the Studio `brand.json`, or edit its `pixels` grid to change
   the cat, and rebuild.

The brand faces are Cascadia Mono (wordmark, headlines, labels) and Public Sans (body).
They appear in artwork and documentation only. The chat log keeps the user's font menu,
and the product does not load either face.

## Interface colour system

The log and most chrome read three axes from `web/src/palettes.css`, set as `data-colour`,
`data-shade` and `data-variant` on the root element by `display.ts`.

- **Colour** (14): violet, gray, red, wine, green, ember, solarized, nord, lavender, sepia,
  salmon, ice, cream, mirc. Each sets a hue, two chromas and an accent set.
- **Shade** (12): white, lightest, light, pale, mid, dim, dusk, dark, deep, black, murk,
  twilight. Each sets the background and text lightness; shades 0 to 3 are light.
- **Variant** (4): standard, phosphor (text and accents tint toward the hue), grain (a
  paper-noise texture), contrast (a wider text and line gap).

Derived tokens, computed in OKLCH so every colour spans every shade:

| Token | Meaning |
| --- | --- |
| `--bg`, `--text` | Canvas and ink from the shade axis, hued by the colour |
| `--panel` | 9% text mixed into the canvas; chrome surfaces |
| `--line` | 24% mix; borders and rules |
| `--text-dim` | 55% mix; timestamps, channel labels, secondary text |
| `--aux` | A hue-relative secondary accent for help tabs, config heads and selection |
| `--popline` | A hue-neutral frame for popups: white on dark shades, black on light |
| `--texture` | Set only by the grain variant |

Semantic tokens, set per colour: `--accent` (names, focus, active controls), `--good`
(connected, success), `--danger` (offline bar, errors, bans), `--vip` (VIP badges),
`--wiki` (resource links) and `--spark` (the header rate graph in dark schemes).

The shell stylesheet `web/src/style.css` aliases `--fg` to `--text` and `--muted` to
`--text-dim`, and supplies the fallback shell values before a palette applies (dark
`#151519` / `#1d1d24` / `#e8e6e3` / `#aaa4b7` / `#34343e` / `#b9a5f0`; light
`#faf8f3` / `#efebe3` / `#27232c` / `#665d70` / `#d5cedc` / `#654394`).

Rules:

1. New chrome uses the tokens. No hex in a component rule, except the two retained
   literals (`#status[data-state=connected]` green and the warning amber on the length
   counter) until they are tokenised.
2. The default display is gray at shade 7, system sans at 14px/1.3, line style 4, zebra 2,
   timestamps 2. The gray brand palette is that default, so the header cat matches the
   first screen.
3. The 18 canonical presets in `display-data.ts` are retained verbatim. Adding a preset is a parity
   question, not a brand one.

## Display option labels

Settings shows readable option text while retaining the existing option values,
order, storage and share-URL parameters. `display-data.ts` exports the per-field
label map and formatter from `display-option-labels.ts`; the labels load with the
Settings editor. Numeric measurements include units, and font keys display the
font's proper name. Preset labels use spaces and an initial capital; their keys
and definitions stay unchanged.

| Field | Stored value → displayed meaning |
| --- | --- |
| Header mode (`min`) | `0` Full header; `1` Compact header; `2` Graph header |
| Composer autohide (`bauto`) | `0` Always visible; `1` Fade until hovered or focused; `2` Collapse until hovered or focused |
| Link and profile cards (`peek`) | `0` Off; `1` Text cards; `2` Cards with images and players; `3` Compact cards |
| Columns and rail (`split`) | `1` One chat column; `2` Two chat columns; `3` Three columns (two in portrait); `4` Chat + video, emotes and stats; `5` Chat + video and emotes; `6` Chat + emotes |
| Subscriber months (`sub`) | `right` / `left`: Full label on the right / left; `num-right` / `num-left`: Number on the right / left; `hidden`: Hidden |
| Emote-only size (`eonly`) | `0` Enlarged emotes; `1` Enlarged emotes aligned right; `2` Normal emote size |
| Hidden-user mode (`hideMode`) | `vanish` Remove the message; `stub` Show a hidden-message label; `ghost` Dim the message |
| Separators (`lines`) | `0` Off; `1` Subtle (25%); `2` Medium (50%); `3` Strong (75%); `4` Full (100%) |
| Zebra (`zebra`) | `0` Off; `1` Subtle (20%); `2` Light (40%); `3` Medium (60%); `4` Strong (80%) |
| Timestamps (`times`) | `0` Hidden; `1` 24-hour · hours and minutes; `2` 24-hour · hours, minutes and seconds; `3` 12-hour · hours and minutes; `4` 12-hour · hours, minutes and seconds |
| Text shadow (`shadow`) | `0` None; `1` Soft text-colored shadow; `2` Medium text-colored shadow; `3` Strong text-colored shadow; `4` Dark shadow; `5` Strong dark shadow |
| Nick shimmer (`anim`) | `0` Off; `1` Slow; `2` Medium; `3` Fast |
| Rainbow motion (`rbw`) | `0` Sweep; `1` Wave; `2` Hue rotation; `3` Pulse; `4` Flicker |
| Font/resource link weight (`weight`, `lw`) | `300` Light; `400` Regular; `500` Medium; `600` Semibold; `700` Bold; labels also show the numeric weight |
| Header font size (`hfs`) | `0` Follow chat font size; positive values use px |
| Help font size (`hpfs`) | `0` Follow chat font size; `-1`, `-2`, `-3`: One, Two or Three size steps smaller than chat; positive values use px |
| Other measurements | Size uses px; line height uses × font size; spacing uses em (`0`: Normal); scrollback uses rows |

These labels describe retained display values; they do not add behavior. The
workbench keeps its single compact top bar, so the legacy header-mode values do
not change that shell. Rail presets apply in landscape and remain subject to
the existing video and pane settings. Preview image/player permissions and
reduced-motion preferences still take priority over their display modes.
The shimmer speed also sets rainbow animation speed; its Off value stops both.
Rainbow mode zero means Sweep, not Off. Help's negative sizes count positions in
the font-size menu, rather than subtracting pixels.

## Typography

- Chat font: `ui-sans-serif` system stack at 14px by default; the user chooses from 29
  stacks (bundled: OpenDyslexic, Fixedsys, Gohu, Hack, Terminess, Roobert, Mononoki,
  Elstob, Cursed, Glean, Miniwi, Web437 VGA; Google Fonts: Atkinson Hyperlegible and
  Mono, Comic Neue, Fira Code, IBM Plex Mono, Inter, JetBrains Mono, Lexend, Shantell
  Sans, Source Code Pro, Source Sans 3, VT323; and system serif stacks).
- Axes: size 7 to 32px, line height 0.6 to 2.5, weight 300 to 700, letter spacing
  -0.08 to 0.12em. Header and help font sizes can follow the chat size or be set apart.
- Chrome inherits the chat font. Status, timestamps, chips and footer run 10 to 12px.
- Stats list headings are 13px in `--accent`; picker section headings are 12px. Nothing in the shell is set in a brand face.

## Components

- **Top bar.** One 38px row on `--panel`: the pixel cat and name as the menu button,
  joined-channel chips with a `+` to join more, a connection dot (`--good` live, amber
  reconnecting, `--danger` failed) with a short state word, the rate sparkline, the
  search button (Ctrl+K or Command+K) and the login or account control. Nothing else is
  a button in the bar. The original header stays in the document, hidden, so feature
  modules keep inserting their trigger buttons there; `src/shell/registry.ts` mirrors
  every one of them as a command. The `data-min` header modes and the strip and graph
  variants no longer apply.
- **Menu and palette.** The cat opens a column menu grouped as Chat, View, Account,
  Moderation, Providers, Integrations and Help, with bindings as `kbd` hints and the
  current placement of docked panels. The palette is a 620px dialog with one search box
  over the same commands, the keyboard actions and quick-switch targets; prefix,
  substring and subsequence matches rank in that order.
- **Workbench.** The chat column sits between three dock zones (left, right, bottom)
  separated by 4px `--line` splitters that turn `--accent` on hover or focus. Any dialog
  or panel gets a 28px chrome bar: uppercase 10px title (the drag handle), a placement
  menu (dock left, right or bottom, float, open as dialog, move, close) and a close
  button. Docked panels stack with share splitters between them; floating panels are
  fixed, resizable, 6px-cornered on `--popline` with the panel shadow. Dragging a title
  detaches the panel; dropping within 40px of an edge or onto a zone docks it. The
  "columns and rail" display option docks video, emotes and stats on the right. Layout
  persists per profile and travels in workspaces as the `workbench` settings part.
- **Notice bars.** The offline bar sits on `--panel` with a `--danger` bottom rule. The
  update-ready control is a normal button. The stream bar and room-state bar are 12px
  `--muted` on a `--line` rule.
- **Log row.** Time and channel in 12px `--muted`; badges 18px; name bold in the user's
  colour or `--accent`; subscription, bits and first-message chips as 10px outlined
  pills; message text; a quoted reply as a `blockquote`. Modifiers: `.action` italic,
  `.removed` struck through at 50%, `.system-message` at 80%, `.target-message` with a
  1px accent outline on `--panel`. Zebra striping and separators follow the display axes.
- **Composer.** Picker button, send-target select, reply target line, an autogrowing
  textarea capped at 160px, the length counter (amber at the warning threshold), send
  button and a 12px status line. The completion list is a `--bg` box with `--line` border;
  the selected option is `--line` with `--accent` text.
- **Emote picker.** A fixed, resizable 560×440 panel on `--panel` with a 6px corner,
  header search, tab and setting rows at 12px, a grid of `--picker-cell` (64px) buttons
  and a recent row. The handle moves it; geometry is saved.
- **Dialogs.** `--panel` with a `--popline` border, 8px corner, the panel shadow and a
  40% black backdrop; 16px padding with the chrome bar bleeding to the edges. Content is
  normalised by `src/shell/shell.css`: paragraphs, headings, fieldsets and sections span
  the width; labelled fields form a responsive grid at 200px minimum; checkbox labels
  stay inline; loose buttons flow in rows. Display settings are grouped into Theme,
  Type, Rows, Filters, Alerts, Composer, Links and cards, Layout and Motion fieldsets.
  Video, whispers, help and the emote picker keep their own open and close logic but
  dock and float through the workbench like any dialog.
- **Cards** (identity preview, link preview). Fixed 360 and 380px panes with 12px padding
  that follow the dialog frame; `--popline` is the hue-neutral frame colour for popups.
- **Rate sparkline.** 72×18 in the top bar, `--accent` stroke.
  Stats dialog graphs are 80px tall in `--accent`.

## States

Dense panels use labelled fieldsets for the first task and native
`details`/`summary` disclosures for specialist tools and longer explanations.
Shared `panel-section`, `panel-details` and `panel-actions` markup keeps labels,
focus and wrapping action rows consistent. A fieldset containing only buttons or
status text remains visible; visibility is explicit rather than inferred from
the presence of labels. Presentation search hides nonmatching fields and empty
groups while keeping edited controls intact. Consent, reviewed data and action
outcomes stay beside their controls. See [the six-panel layout checks](dense-panels.md).

| State | Treatment |
| --- | --- |
| Connecting | Status text "Connecting…" in `--muted` |
| Connected | Status in green (`#63ba8e`, to be tokenised as `--good`) |
| Reconnecting or failed | Status in `--muted` with the reason; gap markers in the log |
| Offline | The offline bar; sending disabled; saved history stays readable |
| Update ready | The reload button appears under the header |
| Disabled control | 60% opacity, default cursor |
| Hover | Button border turns `--accent`; top bar and chrome buttons tint 8% `--fg` |
| Row controls | Thread, bookmark, reply and permalink controls collapse until the row is hovered or focused |
| Selected completion | `--line` background, `--accent` text |
| Pressed toggle | `aria-pressed="true"` draws the `--accent` border and text |
| Target message | 1px accent outline on `--panel` |
| Removed message | Strike-through at 50% opacity |

Managed panels use a shared lower sheet at widths up to 700 px or in portrait.
Open-panel tabs retain drafts and expose one panel at a time; chat stays above
the sheet. Desktop placements return when the viewport widens to landscape.
See [compact panel behavior and verification](compact-panels.md).

## Motion and accessibility

- `prefers-reduced-motion: reduce` removes every animation, transition and smooth scroll,
  including nick shimmer and rainbow names. The display options also expose nick shimmer,
  rainbow motion and the freeze-emotes toggle.
- The log is `role="log"` with `aria-live="off"`; a separate polite announcer carries
  mentions and status. Panels are dialogs with labels; handles are keyboard movable.
- Contrast is the user's responsibility within the palette axes; the contrast variant
  widens the gap for any colour. Defaults and brand roles meet 4.5:1 for text.
- Compact shell panels share at most 48% of the workbench height; chat and its
  composer retain the full viewport width above them.

## Do and do not

- Do use the tokens for any new chrome, and the brand palettes only for icons, marketing and
  documentation.
- Do keep the cat's pixel grid exact; scale with crisp edges, do not redraw or smooth.
- Do not restyle the log row, the palettes or the presets for brand reasons.
- Do not put Twitch's glyph, wordmark or purple in the identity.
- Do not show fabricated chat messages in promotional artwork; rows are bars.
