# Provider reload shortcut and cheer stacking

F5 now invokes the existing public provider metadata reload for joined workspace channels. It retains the 30-second client cooldown and the server cache, leaves the page and chat connection intact, and is available in the action palette and shortcut editor. It runs outside editable fields and modal dialogs; pinned rail panels do not block it. In an editable field or modal, normal browser F5 behavior remains available. The binding can be changed or disabled. Other actions cannot use bare F5, and existing reserved-browser/privacy conflicts are still rejected.

The optional Combine recognized cheers preference defaults off. Recognized cheers show their numeric amount alongside the image. Stacking combines them into the first recognized cheer style only when there are at least two recognized cheer tokens and their safe-integer sum equals the supplied Twitch bits total. The combined image uses the total’s tier and displays that total. Unknown/custom prefixes, missing totals and mismatches keep their original presentation. This is a browser adaptation for the existing recognized cheer prefixes; it does not discover channel-specific custom cheer catalogs. Source message text, archive records, native ranges and the total-bits chip remain unchanged.

Build the web app, run `python3 web/test-support/provider-browser-fixture.py` and open http://127.0.0.1:5192/?channel=current&video=off. Focus the chat log and press F5 twice. The fixture counts should show one additional metadata read and no second read during cooldown, while window.fixtureBootID and fixtureChatSockets remain unchanged. The status announces the cooldown. In Provider and badge preferences, review/apply Combine recognized cheers. The fixture’s Cheer100/Kappa50 message changes from two images and amounts to one Cheer150 image and amount 150. Disable stacking and verify separate amounts return.

Native T3 preview on 2026-10-13 verified metadata reads 1 → 2 → 2 across the two F5 presses, the same boot ID, one chat socket, zero provider writes, and the 100/50 → 150 cheer display. Regression tests cover editable/modal/IME guards, shortcut conflicts, exact totals, unknown prefixes, safe integers, retained source text and missing bits. Full checks are recorded in the PR. Positive live cheer/provider acceptance and channel-specific custom cheer catalogs remain separate.
