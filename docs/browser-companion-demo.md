# Watched-channel browser companion (#36)

The optional Chromium Manifest V3 extension in `companion/browser` reads the active Twitch tab URL only after **Send watched channel**. It stages a validated channel login in a paired Chatty Cat tab. The web app then requires a destination review and **Open reviewed channel**; pairing, polling and receiving a channel do not change local workspaces.

## Install and pair

Open the browser's extension manager, enable developer mode and load `companion/browser` unpacked. The extension requests `activeTab` and `storage` only. It has no content scripts, persistent Twitch host permission, cookie access or native-messaging permission. Its externally-connectable allowlist is `https://chat.subcult.tv/*`; the protocol additionally accepts only that exact origin, the top-level app root and the paired tab. See Chrome's [external messaging](https://developer.chrome.com/docs/extensions/develop/concepts/messaging) and [activeTab permission](https://developer.chrome.com/docs/extensions/develop/concepts/activeTab).

In the extension popup, **Generate new pairing code (unpairs)** displays its extension ID and a five-minute one-use code. In the signed-in app's **Browser companion** panel, enter both and pair. No app CSRF value, OAuth secret, workspace record, private message or embedded-player identity is forwarded. A capability and account ID bind one app tab. The pairing capability stays in extension session storage and the app page's memory; it is not synced or stored in app profiles. The extension's session storage uses its default restriction to trusted extension contexts.

The app can optionally remember up to eight compatible extension IDs by a local name for the current signed-in account. **Remember browser companion ID** saves only the ID/name; selecting a saved record fills the ID/name fields and clears the temporary code. Manual ID entry remains available. Registration, selection and forgetting make no extension request, install nothing and grant no permission. The registry is account-local, bounded to 4 KiB and excluded from workspace export and device sync. Codes, capabilities and app authentication data are never saved in it.

One bridge remains active at a time. Identity/registry fields lock while pairing or paired; unpair before choosing or editing another companion. Reopening an active bridge retains its selected ID. Account/session changes and privacy clear registry controls as well as pairing; saved records remain in their own account store. Stale edits/selections report another-tab changes and retain that tab's data. Unreadable or invalid records remain untouched, and the manual pairing flow remains available. A saved ID must still belong to an installed compatible Chromium companion and requires its fresh one-use code.

Choose a saved destination workspace. Switching away from the active workspace is off until **Allow switching to the selected workspace** is checked. Pair and use **Return to chat; keep browser bridge connected** to keep the app's five-second poll alive. Ordinary close disconnects. Pairing expires after eight hours, or if the app heartbeat is absent for two minutes. The heartbeat lease allows minute-long background timer delays with scheduling margin; popup sends do not renew it. Ordinary reload, account/session change, privacy, explicit unpair, tab removal and detected extension removal clear the bridge. Revocation on page teardown is best effort; the heartbeat expiry is the fallback. A frozen or discarded app tab can still lose pairing.

On a Twitch channel page, open the extension and click **Send watched channel**. Only a canonical HTTPS `www.twitch.tv/<channel>` page is accepted; reserved routes, other hosts, credentials and arbitrary URLs are refused. Queries/fragment are not forwarded. The popup's **Focus paired Chatty Cat tab after sending** preference defaults off and is saved only in extension-local storage. It requests tab/window focus only on that explicit send action.

The app stages the latest channel for review. There is no automatic approval popup: reopen **Browser companion**, choose **Review received watched channel**, then **Open reviewed channel**, even if the channel is already in the workspace. Confirming adds it to the selected saved workspace without removing existing channels, selects that send target, reconciles bounded panes and reloads the selected workspace. Existing reader records and preferences remain. Concurrent workspace edits or a changed account/destination invalidate review. No chat message is sent. Extension popup errors and app connection failures require explicit reconnect; no native process is available through this bridge.

Companion **0.1.2 or newer** resumes pairing after that explicit confirmation. Before navigating, the app arms a one-use handoff valid for 30 seconds in the extension and saves its code, destination, extension/account IDs and a session fingerprint in this tab's `sessionStorage`. No pairing token, CSRF value or OAuth credential is written there, sent in the URL, or synced. The new page consumes the record, checks the same authenticated account/session and destination, and resumes only in the original top-level app tab. The extension rotates the pairing token, clears the consumed handoff and retains the original eight-hour expiry. Other tabs, destinations, accounts, expired codes and replays are refused. Failed preparation or a changed review cancels navigation; unavailable tab storage prevents handoff rather than navigating with an unverified bridge. Ordinary reload has no handoff and still disconnects. Updating both the app and the unpacked extension is required.

## Verification and limits

Regression tests exercise the actual extension protocol and web controller/UI: exact origin/tab/account binding, one-use code, pairing/heartbeat expiry, poll cooldown, URL rejection, no secret forwarding, no mutation on pair/poll/review, stale-destination refusal, privacy/session revocation, channel-capacity refusal and layout/reader preservation. Registry tests additionally cover eight-ID/size limits, strict ID/name-only records, account isolation, stale edits, selection without requests, paired-field locking and active-selection retention. The extension worker serializes session-storage changes across popup and external messages. Only the latest watched channel is retained for two minutes, with a bounded sequence number.

The automated browser-runtime fixture is synthetic. An installed-extension repeated-send round trip after confirmed navigation, browser removal and tab-focus behavior still need owner acceptance in Chromium. The owner reached delivery and review with 0.1.1; its confirmation reload ended pairing. Firefox and Safari are unavailable for this initial `externally_connectable` adaptation; no cross-browser claim is made. Installing an extension does not make the embedded Twitch player share the app's OAuth account. Chat and native playback work without the extension.

The navigation fixture at `http://127.0.0.1:5187/test-support/browser-handoff.html` uses the real web controller/panel and pure extension protocol, with synthetic extension state held in fixture-local storage across actual page navigation. Pair once, stage a channel with `window.fixtureSend('patrick__eff')`, review/confirm, then stage another channel after the page resumes. `window.fixtureTrace()` records request kinds and navigation destinations without credentials. The fixture does not contact Twitch or an installed extension.

This fixture does not establish installed-extension acceptance or native-messaging host registration.
