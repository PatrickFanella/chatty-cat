# Supplemental public EventSub context

Public message context is an explicitly connected, account-scoped supplement to the existing public IRC/history feed. It subscribes to channel.chat.message and channel.chat.notification for one joined channel using user:read:chat. The source contract follows Twitch’s [subscription types](https://dev.twitch.tv/docs/eventsub/eventsub-subscription-types/#channelchatmessage) and [event reference](https://dev.twitch.tv/docs/eventsub/eventsub-reference/#channel-chat-message-event).

The server projects only message/author identifiers and supported source-room, source-message, source-badge/login, source-only, custom-reward, message-type and watch-streak fields. It drops body text, fragments, reply bodies, credentials and unrelated fields. Own held-message events use their separate private feed and are rejected here. The supplemental transport cannot create a public message. The browser requires an existing public message with matching command, received channel, room ID, author ID, message ID and nearby timestamp. Local echoes and imported-history rows are ineligible. Conflicting native identity fields are retained. Existing public bodies, timestamps, sender identity and reply targets never change.

Matching tags enrich rendering and archive/rule predicates. Late enrichment updates retained public rows without repeating message observations, alerts or counters. Unmatched context waits in bounded memory and may enrich a later genuine public message. Public enrichment can be saved with that message; disconnect/privacy clears the supplemental cache rather than deleting existing public history. This is not an alternate general-purpose EventSub chat transport or a way to publish a held private body.

Opening the dialog makes no subscription. Connect requires current consent; grant permission through its login link if needed. Return to chat; keep context connected explicitly hides the dialog while keeping the feed active. The toolbar identifies the connected channel. Ordinary close, disconnect, transport failure, account/session/channel change, privacy and page unload close the source and clear pending context. Native EventSource automatic retry is closed; reconnect is explicit.

Bounds: latest 100 relevant metadata records / 15 minutes, 2 KiB per row, 64 KiB provider frames and 256 KiB browser snapshots. Steady-state snapshots are capped at one per two seconds. Recent EventSub IDs have a rolling 1,000-entry replay window. Each account can share one context channel across up to four tabs; all private/context hubs share the existing 16-hub cap and 12 setup reads per account per minute. Context also takes one shared chat-admission lease and uses the personal-chat join-rate budget. Failure, disconnect and shutdown release admission. Session authorization is checked before every streamed snapshot; credentials remain server-held.

To reproduce, build with `npm --prefix web run build`, then run `go run ./web/test-support/chat-context` and open http://127.0.0.1:5197/?channel=one&video=off. The fixture uses the real OAuth, session, EventSub and SSE handlers with synthetic loopback credentials; it sends no real Twitch action.

1. Sign in as fixture Alice. Open Public message context, follow Grant public context read permission, sign in again and connect explicitly. The fixture count reports two subscriptions and one socket.
2. Use Fixture: public context and Fixture: watch streak. After the next two-second snapshot, the existing public rows gain source #origin, supplied source badges, reward ID, a labelled effect fallback, and a 10-stream / 0-point streak.
3. Use Fixture: unmatched context and Fixture: private held frame. Neither creates another public row. The event-body/token/private-held canaries must be absent from both UI and IndexedDB.
4. Use Fixture: deliver later public message. That public message receives its cached context while retaining its actual public body. Use Return to chat; keep context connected. The dialog closes and the socket remains active. Enable privacy; the socket count returns to zero and supplemental records clear.

Native T3 preview verified these steps on 2026-10-13. IndexedDB held exactly three public rows with the three actual public bodies and no private/body/token canary. Counts were two read subscriptions, one socket while explicitly connected, zero sockets after privacy and zero chat/moderation writes. Unit and real-session stream tests additionally cover replay/rolling bounds, malformed fields, wrong actor/room, cross-account selection rejection, shared tabs, logout, chat-admission refusal/release and unchanged public bodies. Full checks are recorded in the PR.

This implementation is deployed in release 5892994. The owner confirmed consent and a Live public-context connection on October 13. Positive live shared-chat/reward/streak/effect acceptance remains open. A controlled eligible/live broadcaster is required for some positive event cases. Fixtures do not close those gates.
