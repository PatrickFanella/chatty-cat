# M4 optional device sync progress

Issue #29 now has a manual, opt-in browser flow over the private per-account server store. Open Device sync, connect, select categories, review the exact public JSON and record identities, then confirm publish, apply or delete. Opening the panel alone makes no sync requests. Disconnect, close, account/session change and privacy clear pending reviews and abort requests. Export downloads the reviewed public selection. This does not establish deployed or live-account acceptance or close M4.

Snapshots contain selected workspaces, common display/presentation/picker/provider/link preferences, and public bookmark excerpts. The review identifies public rule/command/filter text and bookmark authors, text and timestamps. Private bookmark notes/tags, nickname annotations, drafts, whispers, moderation journals, own-message feedback and source-device reader positions are excluded. Unknown record fields are rejected by the server; browser projections use the existing portable parsers. Destination reader anchors remain local for retained workspaces and matching pane configurations.

Publish replaces the selected account snapshot; omitted categories are removed from that server snapshot. Apply replaces only selected local categories, reports removed records and older incoming bookmark timestamps, preserves annotations on retained bookmarks, and saves removed annotations in a separate local-only backup. If that backup already holds different annotations for the same bookmark, apply stops with both copies retained. Export and a separate reviewed clear action allow reconciliation. Applying a snapshot selects its active workspace and reloads the view without the old view overwriting it on unload.

Mutations require a fetched revision (If-Match), CSRF, current account header and request ID. Concurrent writes are rejected. Failed requests never retry automatically; explicit retry of the same reviewed request recovers a lost receipt without another revision. Apply checks the server revision again and rejects changed local storage before writing. A bounded local recovery journal stores prior values and hashes of intended writes. Startup leaves a fresh 30-second apply lease alone, then conditionally rolls back interrupted writes without replacing observed newer local edits. Recovery conflicts require review. Local backup exports can contain private annotations and are never uploaded.

Deletion clears active server data but retains a minimal revision tombstone, so stale/offline clients cannot recreate deleted data. OAuth credentials remain server-held. Storage is disabled unless CHATTHING_SYNC_DIR is configured. A dedicated 0700 directory, 0600 files, exclusive Linux/macOS lock, atomic rename and fsync protect the one-writer store. Limits are 1,024 accounts, 64 MiB total and two MiB per document. HTTP requests also have size, depth, collection, token, deadline and concurrency bounds. Authorization is checked again after body read; responses are no-store and same-origin.

For container deployment, provision the separate durable directory for UID/GID 10001, mode 0700, then include deploy/compose.sync.yaml. Do not share it with uploads or another writer. This work does not provision or enable production storage. Downloaded copies and operator backups have separate retention. See [the reproducible demo](device-sync-demo.md).
